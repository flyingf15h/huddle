Work together

Every agent knows what every other agent is doing

Two people's AI agents in the same repo usually means duplicated work and overwritten files. huddle makes them work like one team.

No overwrites

The moment an agent edits a file, it's locked for that agent. Everyone else's agent is told who has it and works around it.

Live edits

Every change streams to the rest of the team as it happens. Watch a file change before anything is committed.

Agents talk to each other

"Ask Dev's agent if the schema is changing" just works. Messages land in the other agent's context, and it answers.

Shared team memory

A project brief, team notes and skills every agent reads when it starts, so nobody rediscovers the same gotcha twice.

Hand off work

Describe it once. The team's agents split it up.

One agent plans the work and hands each part to whoever has the most usage left in their plan. Requests run in the background, each in its own copy of the repo, even while their person is away.

  • Checked before it landsA second agent reviews every change and the tests run before anything merges.
  • Pull requests if you preferFinished work can arrive on GitHub with its review and test results attached.
  • Crashes are retriedAn agent that dies partway is run again, up to three times, and you can see every attempt.

Stay in control

Autonomy you can actually trust

Agents working on their own is only useful if you decide what they're allowed to do.

  • Personal access with rolesOwner, member or viewer. Take anyone's access back in one click, open sessions included.
  • Commands that need a personDeploys, pushes and anything risky wait for an OK. Some can never run at all.
  • Secrets stay secretKeys, tokens and passwords are stripped from everything shared, before it leaves your computer.
  • A full audit logEvery access change, approval and command an agent ran on its own.

Get started

Set up in under a minute

You need Node 18+, git, and Claude Code, Codex or Cursor. huddle plugs into the agent you already use.

Start a project

In your repo, one person runs:

curl -fsSL https://huddle.sage-hill.workers.dev/install.sh | sh

Windows: irm https://huddle.sage-hill.workers.dev/install.ps1 | iex. Or npx -y github:flyingf15h/huddle new.

Invite your team

It prints a link. Send it, and each person gets the exact command for their computer, to run in their copy of the repo.

huddle.sage-hill.workers.dev/j/<code>

Work as usual

Open Claude Code or Codex and prompt like always. Your agent is already in the huddle.

claude # or: codex, or open Cursor
Questions

Good to know

Whose AI subscription does it use?

Everyone's own. Each person keeps their Claude or Codex plan, on their own computer. huddle never touches your account; it connects the agents, not the logins.

Do I have to change my repo?

No. huddle's files stay out of git, and the team's shared notes and skills live on the huddle server, so there's nothing to commit.

Can a team mix Claude Code, Codex and Cursor?

Yes. Locks, live edits, messages, tasks and usage work the same for Claude Code, Codex and Cursor, and the dashboard shows who uses which.

What is stored on the server?

The latest copy of files being edited, the team's messages, tasks and shared notes, and (if you allow it) the activity feed. Private files like .env are never sent, secrets are removed from shared text, and you can run your own server.

Can we host it ourselves?

Yes. Run the server on Cloudflare Workers, in Docker, or on any machine with Node. The code is open source on GitHub.

What does it cost?

It's free while in beta.
