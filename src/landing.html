Every agent knows what the others are doing

Two people's agents in the same repo usually means duplicated work and overwritten files. huddle has them work like one team.

No overwrites

The moment an agent edits a file, it's locked for that agent. Everyone else's agent is told who has it and works around it.

Live edits

Every change reaches the rest of the team as it happens, so you can watch a file change before anything is committed.

Agents talk to each other

"Ask Dev's agent if the schema is changing" just works. The message lands in the other agent's context, and it answers.

Shared team memory

A project brief, team notes and skills every agent reads when it starts, so nobody rediscovers the same gotcha twice.

Describe it once, and the team's agents split it up

One agent plans the work and hands each part to whoever has the most usage left in their plan. Requests run in the background, each in its own copy of the repo, even while their person is away.

  • Checked before it landsA second agent reviews every change and the tests run before anything merges.
  • Pull requests if you preferFinished work can arrive on GitHub with its review and test results attached.
  • Crashes are retriedAn agent that dies partway is run again, up to three times, and you can see every attempt.

Autonomy you can actually trust

Agents working on their own are only useful if you decide what they're allowed to do.

  • Your conversation stays yoursTeammates see which tools your agent ran, not what you said to it, unless you choose to share more.
  • Commands that need a personDeploys, pushes and anything risky wait for an OK. Some can never run at all.
  • Secrets stay on your computer.env files and keys are never uploaded, and tokens are stripped from everything shared.
  • Access you can take backOwner, member or viewer, with an audit log of every access change, approval and command an agent ran on its own.

Set up in about a minute

You need Node 18 or newer, git, and Claude Code, Codex or Cursor. huddle plugs into the agent you already use.

1

Start a project

In your repo, one person runs:

curl -fsSL https://huddle.sage-hill.workers.dev/install.sh | sh

On Windows: irm https://huddle.sage-hill.workers.dev/install.ps1 | iex

2

Invite your team

It prints a link. Each person who opens it gets the exact command for their computer.

huddle.sage-hill.workers.dev/j/<code>
3

Work as usual

Start Claude Code, Codex or Cursor in the folder and prompt like always. Your agent is already in the huddle.

Questions

Whose AI subscription does it use?

Everyone's own. Each person keeps their Claude, Codex or Cursor plan, on their own computer. huddle connects the agents, not the logins.

Do I have to change my repo?

No. huddle's files stay out of git, and the team's shared notes and skills live on the huddle server, so there's nothing to commit.

Can a team mix Claude Code, Codex and Cursor?

Yes. Locks, live edits, messages, tasks and usage work the same for all three, and the dashboard shows who uses which.

What is stored on the server?

The latest copy of files being edited, the team's messages, tasks and shared notes, and which tools each agent ran. Conversations are only shared if a person turns that on. Private files like .env are never sent, secrets are removed from shared text, and you can run your own server.

Can we host it ourselves?

Yes. Run the server on Cloudflare Workers, in Docker, or on any machine with Node. The code is open source on GitHub.

What does it cost?

It's free while in beta.
